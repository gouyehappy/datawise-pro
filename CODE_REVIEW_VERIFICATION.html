三、修复引入的问题

P2FE-07 组件拆分导致工具栏样式回归 — 已收口（47b772f）

SqlConsoleToolbar.vue 从父组件拆出后，工具栏布局类曾仍定义在父组件 sql-console-tab.css，scoped 失配导致 flex 错乱。

现状：已在 47b772f 将布局样式落到 Toolbar 自身 scoped CSS，并同步 ViewModel 工具栏 nowrap；HEAD 不再带该回归。

P2DT-02 移除 registerRoot 导致「重新打开最近工作区」功能失效 — 仍开放

后端 fs:registerRoot 已抛异常，但前端 local-files.service.ts:27 仍调用它；local-files-store.ts 的 openRoot() 因此 reject，重新打开工作区看不到文件列表。workspace 直存能力实际失效（导出降级到下载对话框）。

修复方移除了危险通道却未提供宿主可信的替代路径（如宿主内部按已保存路径调用 registerRoot）。

P1SEC-02 修复把 OIDC 异常 message 写入 URL fragment — 仍开放

AuthController.java:101-102 的 catch 分支 appendFragment(base,"oidcError",ex.getMessage())，虽 fragment 不发往服务端，但会显示在地址栏并经前端 toast 展示，与 SEC-10「异常 message 不回显」目标冲突，属新的信息展示面。

四、值得肯定的高质量修复

本次修复的实质成果集中在几条主攻击链上，质量经逐行核对确认：

• P0 RCE 主链已切断：桌面桥接层新增 DesktopRendererTrust origin 白名单（注入前 + onQuery 二次校验 + 环境变量强校验），配合 registerRoot 收归、JRE 来源收紧，原始「恶意页面 → 全原生能力 → 恶意 java.exe → 重启执行」路径在主路径上不再成立。
